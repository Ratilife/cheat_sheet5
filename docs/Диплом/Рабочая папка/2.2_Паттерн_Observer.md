# 3. Паттерн Observer (Наблюдатель)

Паттерн Observer (Наблюдатель) представляет собой поведенческий паттерн проектирования, предназначенный для организации механизма уведомления зависимых объектов об изменении состояния наблюдаемого объекта. Данный паттерн обеспечивает слабую связанность между объектами, позволяя одному объекту (наблюдаемому, Subject) уведомлять множество других объектов (наблюдателей, Observers) об изменениях своего состояния без необходимости знать конкретные типы этих наблюдателей.

Основная концепция паттерна Observer заключается в установлении отношения "один ко многим" между наблюдаемым объектом и его наблюдателями, где изменение состояния наблюдаемого объекта автоматически приводит к уведомлению всех зарегистрированных наблюдателей. Это позволяет реализовать реактивную архитектуру, в которой компоненты системы автоматически реагируют на изменения в других компонентах, обеспечивая синхронизацию состояния и согласованность данных.

Исторически паттерн Observer был описан в классической работе "Design Patterns: Elements of Reusable Object-Oriented Software" (Gang of Four, 1994) и получил широкое распространение в различных технологических стеках. В контексте разработанного приложения паттерн Observer применяется для отслеживания изменений файлов в файловой системе и автоматического обновления интерфейса при обнаружении внешних изменений, что обеспечивает актуальность отображаемых данных и предотвращает потерю информации при одновременном редактировании файлов несколькими приложениями.

## Структурные компоненты паттерна

### Subject (Наблюдаемый объект) — источник событий

Наблюдаемый объект представляет собой компонент, состояние которого отслеживается другими объектами. Ключевые обязанности наблюдаемого объекта включают управление списком зарегистрированных наблюдателей, предоставление методов для добавления и удаления наблюдателей, уведомление всех зарегистрированных наблюдателей об изменении состояния, а также инкапсуляцию логики отслеживания изменений и генерации событий.

Практической реализацией наблюдаемого объекта в приложении является класс `FileWatcher` (расположенный в `src/observers/file_watcher.py`). Данный класс наследуется от `QObject` и использует механизм сигналов Qt для реализации паттерна Observer. Класс инкапсулирует функциональность отслеживания изменений файлов и директорий в файловой системе через использование `QFileSystemWatcher` из библиотеки Qt, который предоставляет низкоуровневый доступ к событиям файловой системы операционной системы.

Класс `FileWatcher` определяет следующие сигналы для уведомления наблюдателей:

- `file_updated` — сигнал об изменении файла (путь к файлу)
- `debounced_file_updated` — сигнал об изменении файла после дебаунсинга (оптимизация для предотвращения множественных срабатываний)
- `file_deleted` — сигнал об удалении файла (путь к удаленному файлу)
- `dir_changed` — сигнал об изменении директории (путь к измененной директории)
- `watching_paused` — сигнал о статусе паузы отслеживания (булево значение)

Класс предоставляет методы для управления отслеживанием: `watch_file(path)` для добавления файла в список отслеживаемых, `watch_directory(dir_path)` для рекурсивного отслеживания директории и всех её подпапок, `remove_path(path)` для прекращения отслеживания, `pause(duration)` для временной приостановки отслеживания (полезно при сохранении файла для избежания циклических обновлений), `resume()` для возобновления отслеживания.

Важной особенностью реализации является использование механизма дебаунсинга (debouncing) для оптимизации производительности. При обнаружении изменения файла система не сразу уведомляет наблюдателей, а запускает таймер с задержкой 300 миллисекунд. Если в течение этого времени происходит еще одно изменение, таймер перезапускается. Это предотвращает избыточные обновления при частых изменениях файла (например, при автоматическом сохранении) и снижает нагрузку на систему.

### Observer (Наблюдатель) — получатель уведомлений

Наблюдатель представляет собой интерфейс или абстрактный класс, определяющий метод обновления, который вызывается наблюдаемым объектом при изменении его состояния. Ключевые характеристики наблюдателя включают определение единого интерфейса для всех конкретных наблюдателей, обеспечение полиморфизма при обработке уведомлений, а также инкапсуляцию логики реакции на изменения состояния наблюдаемого объекта.

Практической реализацией базового наблюдателя в приложении является класс `MyBaseObserver` (расположенный в `src/observers/my_base_observer.py`). Данный класс наследуется от `QObject` и определяет общий функционал для всех наблюдателей в системе. Класс предоставляет набор сигналов для уведомления других компонентов о событиях, связанных с файлами:

- `file_selected` — сигнал при выборе файла (путь к файлу, объект)
- `file_changed` — сигнал при изменении файла (путь к измененному файлу)
- `file_deleted` — сигнал при удалении файла (путь к удаленному файлу)
- `file_created` — сигнал при создании файла (путь к созданному файлу)
- `file_saved` — сигнал при сохранении файла (путь к сохраненному файлу)

Класс также предоставляет методы для управления отслеживанием файлов: `watch_file(path)` для добавления файла в отслеживаемые, `unwatch_file(path)` для прекращения отслеживания, `is_watched(path)` для проверки, отслеживается ли файл.

### ConcreteObserver (Конкретный наблюдатель) — конкретные реализации

Конкретные наблюдатели представляют собой реализации интерфейса наблюдателя, каждая из которых определяет специфичную реакцию на уведомления от наблюдаемого объекта. Каждый конкретный наблюдатель подписывается на интересующие его события и реализует логику обработки этих событий в соответствии со своими требованиями.

Практическими реализациями конкретных наблюдателей в приложении являются следующие классы:

- **STEditor** (`src/editor/st_editor.py`) — редактор для файлов Structured Text, который подписывается на сигналы `FileWatcher` для отслеживания изменений открытых файлов. Редактор обрабатывает события `debounced_file_updated`, `file_deleted`, `dir_changed`, `watching_paused` и реализует логику автоматического обновления содержимого при внешних изменениях, обнаружения конфликтов при одновременном редактировании, перевода файла в режим только для чтения при удалении, а также управления состоянием отслеживания.

- **MarkdownEditor** (`src/editor/markdown_editor.py`) — редактор для Markdown-файлов, который аналогично `STEditor` подписывается на сигналы `FileWatcher` и реализует специфичную для Markdown логику обработки внешних изменений, включая обновление как исходного текста, так и его визуализированного представления.

- **SidePanel** (`src/ui/side_panel.py`) — боковая панель приложения, которая подписывается на сигналы `FileWatcher` для отслеживания изменений в структуре файлов проекта. Панель обрабатывает события `file_updated`, `file_deleted`, `dir_changed` и реализует логику обновления дерева файлов, инвалидации кэша при изменениях, запуска повторного парсинга измененных файлов, а также синхронизации отображаемой структуры с файловой системой.

- **FileEditorWindowObserver** (`src/ui/file_editor.py`) — наблюдатель для главного окна редактора, наследующийся от `MyBaseObserver` и реализующий логику обработки событий, связанных с файлами, в контексте главного окна приложения.

- **SidePanelObserver** (`src/ui/side_panel.py`) — наблюдатель для боковой панели, наследующийся от `MyBaseObserver` и обеспечивающий обработку событий файловой системы в контексте боковой панели.

## Механизм взаимодействия компонентов

Взаимодействие компонентов системы при использовании паттерна Observer организовано таким образом, чтобы наблюдаемые объекты не знали о конкретных типах наблюдателей, а наблюдатели могли динамически подписываться и отписываться от событий. Механизм взаимодействия демонстрирует практическую реализацию принципов слабой связанности и реактивности в контексте отслеживания изменений файловой системы.

В реализации паттерна Observer выделяются следующие ключевые компоненты:

- **FileWatcher** (Subject) — централизованный наблюдаемый объект, отслеживающий изменения файлов и директорий через `QFileSystemWatcher`
- **MyBaseObserver** (Observer) — базовый класс, определяющий общий интерфейс для наблюдателей
- **STEditor, MarkdownEditor, SidePanel** (ConcreteObserver) — конкретные наблюдатели, реагирующие на изменения файлов
- **Сигналы Qt** — механизм уведомления, обеспечивающий асинхронную коммуникацию между компонентами

Взаимодействие компонентов Observer в проекте реализовано следующим образом:

### 1. Инициализация наблюдаемого объекта → Subject

При инициализации приложения создается экземпляр `FileWatcher`, который настраивает `QFileSystemWatcher` для отслеживания изменений файловой системы. В конструкторе `FileWatcher` выполняется:

- Создание экземпляра `QFileSystemWatcher` для низкоуровневого отслеживания
- Инициализация множества `watched_dirs` для хранения отслеживаемых директорий
- Подключение внутренних обработчиков к сигналам `QFileSystemWatcher`: `fileChanged` → `_handle_file_change`, `directoryChanged` → `_handle_dir_change`
- Настройка механизма дебаунсинга через `QTimer` с интервалом 300 миллисекунд
- Инициализация флага `_watching_paused` для управления паузой отслеживания

### 2. Регистрация наблюдателей → Observer подписка

Конкретные наблюдатели подписываются на сигналы `FileWatcher` при инициализации или при открытии файла. В методе `_connect_file_watcher()` класса `STEditor` выполняется подписка на сигналы:

```python
self._file_watcher.debounced_file_updated.connect(self._process_external_update)
self._file_watcher.file_deleted.connect(self._on_external_file_deleted)
self._file_watcher.dir_changed.connect(self._on_directory_changed)
self._file_watcher.watching_paused.connect(self._on_watching_paused)
```

Аналогично, в методе `_init_observers()` класса `SidePanel` выполняется подписка:

```python
self.file_watcher.file_updated.connect(self._on_file_updated)
self.file_watcher.file_deleted.connect(self._on_file_deleted)
self.file_watcher.dir_changed.connect(self._on_dir_changed)
```

Важно отметить, что подписка происходит через механизм сигналов и слотов Qt, который обеспечивает слабую связанность — `FileWatcher` не знает о конкретных типах наблюдателей, а только испускает сигналы, на которые могут подписаться любые объекты.

### 3. Добавление файлов в отслеживание → Subject регистрация

При открытии файла в редакторе или при инициализации компонента файлы и директории добавляются в отслеживание. В методе `_start_watching_file()` класса `STEditor` выполняется:

```python
if self._file_watcher and self.file_path and self._watching_enabled:
    file_path_str = str(self.file_path)
    self._file_watcher.watch_file(file_path_str)
    self._file_watcher.watch_directory(str(self.file_path.parent))
```

Метод `watch_file()` класса `FileWatcher` вызывает внутренний метод `_add_path()`, который проверяет существование файла и добавляет его в `QFileSystemWatcher` через метод `addPath()`. Метод `watch_directory()` рекурсивно добавляет директорию и все её подпапки в отслеживание через метод `_watch_subdirectories()`.

### 4. Обнаружение изменения → Subject обработка

При изменении файла в файловой системе `QFileSystemWatcher` генерирует событие, которое обрабатывается методом `_handle_file_change()` класса `FileWatcher`. В данном методе выполняется:

- Проверка существования файла через `os.path.exists(path)`
- Если файл существует — вызов метода `_on_external_file_update()` для обработки с дебаунсингом
- Если файл не существует — испускание сигнала `file_deleted.emit(path)`

Метод `_on_external_file_update()` реализует механизм дебаунсинга:

```python
if self._watching_paused:
    return  # Игнорируем если отслеживание приостановлено

self._pending_external_update = file_path
self._debounce_timer.start()
```

Таймер дебаунсинга перезапускается при каждом новом изменении, и только после истечения 300 миллисекунд без новых изменений вызывается метод `_handle_debounced_update()`, который испускает сигнал `debounced_file_updated.emit(file_path)`.

### 5. Уведомление наблюдателей → Observer получение события

Механизм сигналов Qt автоматически вызывает подключенные слоты всех подписанных наблюдателей при испускании сигнала. При получении сигнала `debounced_file_updated` в методе `_process_external_update()` класса `STEditor` выполняется:

- Проверка соответствия измененного файла текущему открытому файлу
- Чтение нового содержимого файла с диска
- Сравнение с текущим содержимым редактора
- Принятие решения на основе состояния:
  - Если содержимое одинаковое — игнорирование (ложное срабатывание)
  - Если файл не был изменен пользователем (`not self.is_modified`) — автоматическое обновление содержимого через `set_content(external_content)`
  - Если файл был изменен пользователем (`self.is_modified`) — испускание сигнала конфликта `file_conflict_detected.emit(current_content, external_content)`

Аналогично, при получении сигнала `file_deleted` в методе `_on_external_file_deleted()` редактор переводит файл в режим только для чтения через испускание сигнала `file_became_readonly.emit(file_path)`.

### 6. Реакция наблюдателей → Observer обработка

Каждый наблюдатель реализует свою специфичную логику обработки уведомлений. В методе `_on_file_updated()` класса `SidePanel` выполняется:

- Инвалидация кэша для измененного файла через `self.content_cache.remove(file_path)` и `self.metadata_cache.remove(file_path)`
- Обновление модели дерева файлов через `self.tree_model_manager.refresh_model()`
- Запуск повторного парсинга файла через `self.background_parser.add_task(file_path, Priority.HIGH)`

При получении сигнала `dir_changed` в методе `_on_dir_changed()` выполняется:

- Обновление структуры дерева файлов для измененной директории
- Пересканирование директории для обнаружения новых файлов и подпапок
- Синхронизация отображаемой структуры с файловой системой

### 7. Управление паузой отслеживания → предотвращение циклических обновлений

Важным аспектом реализации является механизм паузы отслеживания для предотвращения циклических обновлений при сохранении файла. В методе `save()` класса `STEditor` перед сохранением выполняется:

```python
self._file_watcher.pause(3000)  # Пауза на 3 секунды
```

Метод `pause()` класса `FileWatcher` устанавливает флаг `_watching_paused = True`, испускает сигнал `watching_paused.emit(True)` и запускает таймер для автоматического возобновления через указанное время. Во время паузы все события изменения файлов игнорируются в методе `_on_external_file_update()`, что предотвращает обработку изменений, вызванных самим приложением при сохранении файла.

### 8. Отписка наблюдателей → Observer отключение

При закрытии файла или уничтожении компонента наблюдатели отписываются от сигналов `FileWatcher`. В методе `_disconnect_file_watcher()` класса `STEditor` выполняется отключение всех подключенных сигналов:

```python
self._file_watcher.debounced_file_updated.disconnect(self._process_external_update)
self._file_watcher.file_deleted.disconnect(self._on_external_file_deleted)
self._file_watcher.dir_changed.disconnect(self._on_directory_changed)
self._file_watcher.watching_paused.disconnect(self._on_watching_paused)
```

Также выполняется удаление файла из отслеживания через `self._file_watcher.remove_path(file_path_str)` в методе `_stop_watching_file()`.

## Преимущества применения

Применение паттерна Observer в системе отслеживания файлов обеспечивает следующие преимущества:

- **Слабая связанность**: Компоненты системы не зависят друг от друга напрямую, а взаимодействуют через механизм сигналов Qt. `FileWatcher` не знает о конкретных типах наблюдателей, что позволяет легко добавлять новые наблюдатели без изменения кода `FileWatcher`.

- **Реактивность**: Система автоматически реагирует на изменения в файловой системе без необходимости периодического опроса состояния файлов. Это обеспечивает мгновенное обновление интерфейса при внешних изменениях и улучшает пользовательский опыт.

- **Расширяемость**: Добавление нового наблюдателя требует только создания класса, наследующегося от `MyBaseObserver` или реализующего необходимые слоты, и подписки на соответствующие сигналы `FileWatcher`. Существующий код не требует изменений.

- **Централизованное управление**: Все отслеживание файлов сосредоточено в одном компоненте (`FileWatcher`), что упрощает управление, отладку и оптимизацию. Механизм дебаунсинга и паузы отслеживания применяется ко всем наблюдателям автоматически.

- **Множественная подписка**: Несколько наблюдателей могут подписаться на одни и те же события, что позволяет различным компонентам системы реагировать на одни и те же изменения независимо друг от друга. Например, и редактор, и боковая панель могут отслеживать изменения одного файла.

- **Асинхронность**: Механизм сигналов Qt обеспечивает асинхронную обработку событий, что предотвращает блокировку интерфейса при обработке изменений файлов и обеспечивает отзывчивость приложения.

- **Оптимизация производительности**: Механизм дебаунсинга предотвращает избыточные обновления при частых изменениях файла, снижая нагрузку на систему и улучшая производительность приложения.

- **Предотвращение конфликтов**: Система обнаруживает конфликты при одновременном редактировании файла пользователем и внешней программой, уведомляя пользователя и предоставляя возможность выбора действия.

- **Управление ресурсами**: Механизм паузы отслеживания предотвращает циклические обновления при сохранении файлов самим приложением, что исключает ненужную обработку событий и оптимизирует использование ресурсов.

Таким образом, реализация паттерна Observer в системе отслеживания файлов обеспечивает гибкость, реактивность и расширяемость архитектуры, что соответствует принципам современной разработки программного обеспечения и способствует созданию отзывчивой системы, автоматически синхронизирующейся с изменениями в файловой системе.
