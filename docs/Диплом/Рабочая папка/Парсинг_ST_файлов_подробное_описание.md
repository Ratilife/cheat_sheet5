# 2.3.4.1. Парсинг ST-файлов

## Введение

Парсинг ST-файлов (Structured Text) представляет собой процесс преобразования структурированного текстового файла в иерархическую структуру данных приложения. Алгоритм основан на использовании генератора парсеров ANTLR4, который обеспечивает надежный лексический и синтаксический анализ согласно формальной грамматике, описанной в файле `STFile.g4`.

## Общая схема алгоритма

Процесс парсинга ST-файла состоит из следующих последовательных этапов:

1. **Инициализация входного потока** — чтение файла и создание потока символов
2. **Лексический анализ (Lexing)** — разбиение текста на токены
3. **Синтаксический анализ (Parsing)** — построение синтаксического дерева
4. **Обход дерева через Listener** — извлечение структуры данных
5. **Преобразование в структуру приложения** — формирование итогового результата

---

## 1. Алгоритм использования ANTLR4 парсера

### 1.1. Создание входного потока

**Цель этапа:** Преобразование файла в поток символов для последующей обработки.

**Реализация:**
```python
input_stream = FileStream(file_path, encoding="utf-8")
```

**Детали процесса:**
- Класс `FileStream` из библиотеки ANTLR4 открывает файл по указанному пути
- Файл читается полностью в память с указанной кодировкой (UTF-8)
- Создается объект потока, который предоставляет последовательный доступ к символам файла
- BOM (Byte Order Mark) автоматически обрабатывается грамматикой (правило `BOM: '\uFEFF' -> skip`)

**Особенности:**
- Кодировка UTF-8 обеспечивает корректную обработку кириллических символов в именах папок и шаблонов
- Файл должен существовать и быть доступен для чтения
- При ошибке чтения выбрасывается исключение `IOError`

### 1.2. Лексический анализ (Lexing)

**Цель этапа:** Разбиение потока символов на последовательность токенов согласно правилам грамматики.

**Реализация:**
```python
lexer = STFileLexer(input_stream)
tokens = CommonTokenStream(lexer)
```

**Процесс лексического анализа:**

Лексер `STFileLexer` последовательно анализирует символы входного потока и группирует их в токены согласно правилам, определенным в грамматике `STFile.g4`:

**Типы токенов, распознаваемые лексером:**

1. **STRING** — строковые литералы
   - Паттерн: `'"' ('""' | ~["])* '"'`
   - Примеры: `"Папка"`, `"Шаблон"`, `"Содержимое шаблона"`
   - Обработка: двойные кавычки внутри строки экранируются как `""`

2. **INT** — целочисленные значения
   - Паттерн: `[0-9\uFF10-\uFF19]+`
   - Примеры: `0`, `1`, `5`, `123`
   - Поддержка: обычные арабские цифры и полноширинные цифры Unicode

3. **LBRACE** — открывающая фигурная скобка
   - Литерал: `{`
   - Используется для обозначения начала структурных блоков

4. **RBRACE** — закрывающая фигурная скобка
   - Литерал: `}`
   - Используется для обозначения конца структурных блоков

5. **T__0, T__1, T__2** — служебные токены
   - `T__0`: запятая `,`
   - `T__1`: символ `'0'`
   - `T__2`: символ `'1'`

6. **WS** — пробельные символы
   - Паттерн: `[ \t\r\n]+`
   - Действие: `-> skip` (пропускаются, не попадают в поток токенов)

7. **BOM** — маркер порядка байтов
   - Литерал: `'\uFEFF'`
   - Действие: `-> skip` (пропускается)

**Пример лексического анализа:**

Для входной строки:
```
{1, {"Папка", 1, 0, "", ""}, {0, {"Шаблон", 0, 0, "", "содержимое"}}}
```

Лексер создаст следующую последовательность токенов:
```
LBRACE, INT(1), T__0, LBRACE, STRING("Папка"), T__0, T__2, T__0, T__1, 
T__0, STRING(""), T__0, STRING(""), RBRACE, T__0, LBRACE, T__1, T__0, 
LBRACE, STRING("Шаблон"), T__0, T__1, T__0, T__1, T__0, STRING(""), 
T__0, STRING("содержимое"), RBRACE, RBRACE, RBRACE
```

**Особенности:**
- Лексер работает детерминированно, используя конечный автомат (DFA)
- Длинные совпадения имеют приоритет (greedy matching)
- Пробельные символы удаляются из потока токенов, но сохраняют позиции для сообщений об ошибках

### 1.3. Формирование потока токенов

**Цель этапа:** Создание структурированного потока токенов для синтаксического анализатора.

**Реализация:**
```python
tokens = CommonTokenStream(lexer)
```

**Процесс:**
- `CommonTokenStream` оборачивает лексер и предоставляет интерфейс для доступа к токенам
- Токены индексируются и могут быть получены по индексу
- Поддерживается буферизация токенов для эффективного доступа
- Поток позволяет парсеру "заглядывать вперед" (lookahead) для принятия решений о разборе

**Структура токена:**
Каждый токен содержит:
- Тип токена (например, `STRING`, `INT`, `LBRACE`)
- Текстовое значение (например, `"Папка"`, `1`, `{`)
- Номер строки и позицию в строке (для сообщений об ошибках)
- Индекс в потоке

### 1.4. Синтаксический анализ (Parsing)

**Цель этапа:** Построение синтаксического дерева (Parse Tree) согласно правилам грамматики.

**Реализация:**
```python
parser = STFileParser(tokens)
parser.removeErrorListeners()
parser.addErrorListener(ExceptionErrorListener())
tree = parser.fileStructure()
```

**Процесс синтаксического анализа:**

Парсер `STFileParser` использует поток токенов для построения дерева разбора согласно правилам грамматики `STFile.g4`.

**Структура грамматики STFile.g4:**

Грамматика определяет следующие правила:

1. **fileStructure** — корневое правило
   ```
   fileStructure: LBRACE int_value ',' rootContent RBRACE;
   ```
   Структура: `{ <число>, <корневое_содержимое> }`

2. **rootContent** — содержимое корневого уровня
   ```
   rootContent: LBRACE int_value ',' folderContent RBRACE;
   ```
   Структура: `{ <количество_элементов>, <содержимое_папки> }`

3. **folderContent** — содержимое папки
   ```
   folderContent: folderHeader (',' entry)*;
   ```
   Состоит из заголовка папки и списка элементов (через запятую)

4. **entry** — элемент структуры (папка или шаблон)
   ```
   entry:
       LBRACE int_value ',' folderHeader ',' entryList RBRACE  // Папка с содержимым
       | LBRACE int_value ',' folderHeader RBRACE              // Пустая папка
       | LBRACE '0' ',' templateHeader RBRACE;                  // Шаблон
   ```

5. **folderHeader** — заголовок папки
   ```
   folderHeader:
       LBRACE
       STRING ','      // Имя папки
       '1' ','         // Тип (строго 1 для папки)
       ('0' | '1') ',' // Флаги
       STRING ','      // Описание 1
       STRING          // Описание 2
       RBRACE
   ```
   Формат: `{"<имя>", 1, <флаги>, "<описание1>", "<описание2>"}`

6. **templateHeader** — заголовок шаблона
   ```
   templateHeader:
       LBRACE
       STRING ','      // Имя шаблона
       '0' ','         // Тип (строго 0 для шаблона)
       ('0' | '1') ',' // Флаги
       STRING ','      // Описание 1
       STRING          // Содержимое шаблона
       RBRACE
   ```
   Формат: `{"<имя>", 0, <флаги>, "<описание1>", "<содержимое>"}`

**Алгоритм работы парсера:**

Парсер использует алгоритм LL(*) с адаптивным предсказанием (Adaptive LL):

1. **Начало разбора:** Вызов `parser.fileStructure()` запускает разбор с корневого правила
2. **Рекурсивный спуск:** Парсер рекурсивно применяет правила грамматики
3. **Построение дерева:** Для каждого примененного правила создается узел дерева
4. **Обработка альтернатив:** При наличии альтернатив (`|`) парсер использует lookahead для выбора правильной ветви
5. **Завершение:** После успешного разбора возвращается корневой узел дерева

**Пример синтаксического дерева:**

Для файла:
```
{1, {2, {"Папка1", 1, 0, "", ""}, {0, {"Шаблон1", 0, 0, "", "текст"}}}}
```

Дерево разбора будет иметь следующую структуру:
```
fileStructure
├── LBRACE
├── int_value (1)
├── T__0
├── rootContent
│   ├── LBRACE
│   ├── int_value (2)
│   ├── T__0
│   ├── folderContent
│   │   ├── folderHeader
│   │   │   ├── LBRACE
│   │   │   ├── STRING ("Папка1")
│   │   │   ├── T__0
│   │   │   ├── T__2 (1)
│   │   │   ├── T__0
│   │   │   ├── T__1 (0)
│   │   │   ├── T__0
│   │   │   ├── STRING ("")
│   │   │   ├── T__0
│   │   │   ├── STRING ("")
│   │   │   └── RBRACE
│   │   ├── T__0
│   │   └── entry (template)
│   │       ├── LBRACE
│   │       ├── T__1 (0)
│   │       ├── T__0
│   │       ├── templateHeader
│   │       │   └── ...
│   │       └── RBRACE
│   └── RBRACE
└── RBRACE
```

**Обработка ошибок:**

Перед началом парсинга устанавливается пользовательский обработчик ошибок:

```python
parser.removeErrorListeners()  # Удаление стандартных обработчиков
parser.addErrorListener(ExceptionErrorListener())  # Добавление кастомного
```

Класс `ExceptionErrorListener` переопределяет метод `syntaxError`, который вызывается при обнаружении синтаксической ошибки:

```python
def syntaxError(self, recognizer, offendingSymbol, line, column, msg, e):
    raise Exception(f"Ошибка парсинга в строке {line}:{column} - {msg}")
```

Это обеспечивает:
- Детальную информацию об ошибке (строка, позиция, сообщение)
- Немедленное прерывание парсинга при ошибке
- Возможность обработки ошибок на уровне приложения

## 2. Обработка синтаксического дерева через Listener

### 2.1. Концепция паттерна Listener

**Цель:** Извлечение структурированных данных из синтаксического дерева без необходимости управления обходом вручную.

**Принцип работы:**
- Listener реализует паттерн "Наблюдатель" (Observer Pattern)
- Обход дерева управляется классом `ParseTreeWalker` из ANTLR4
- Слушатель реагирует на события входа и выхода из узлов дерева
- Порядок обхода: depth-first (в глубину), слева направо

**Преимущества:**
- Автоматическое управление обходом дерева
- Простота реализации — достаточно переопределить нужные методы
- Предсказуемый порядок обработки узлов
- Идеально подходит для задач извлечения и анализа данных

### 2.2. Структура класса StructureListener

**Наследование:**
```python
class StructureListener(STFileListener):
```

Класс `StructureListener` наследуется от автоматически сгенерированного `STFileListener`, который содержит пустые методы для всех правил грамматики:
- `enterFileStructure(ctx)` / `exitFileStructure(ctx)`
- `enterRootContent(ctx)` / `exitRootContent(ctx)`
- `enterEntry(ctx)` / `exitEntry(ctx)`
- И другие методы для каждого правила

**Инициализация:**
```python
def __init__(self):
    self.stack = [{'children': []}]      # Стек для отслеживания иерархии
    self.current_parent = self.stack[0]   # Текущий родительский элемент
    self.root_name = "Unnamed"            # Имя корневого элемента
    self.found_root = False               # Флаг обнаружения корня
```

**Ключевые компоненты:**

1. **Стек (`self.stack`):**
   - Хранит цепочку родительских элементов (папок)
   - Позволяет отслеживать текущий уровень вложенности
   - При входе в папку элемент добавляется в стек
   - При выходе из папки элемент извлекается из стека

2. **Текущий родитель (`self.current_parent`):**
   - Указывает на элемент, в который добавляются новые дочерние элементы
   - Обновляется при входе/выходе из папок
   - Всегда ссылается на последний элемент стека

3. **Имя корня (`self.root_name`):**
   - Устанавливается из имени файла (без расширения)
   - Используется для идентификации корневого элемента структуры

### 2.3. Обход дерева разбора

**Инициализация обхода:**
```python
listener = StructureListener()
file_name = os.path.splitext(os.path.basename(file_path))[0]
listener.root_name = file_name
ParseTreeWalker().walk(listener, tree)
```

**Алгоритм обхода `ParseTreeWalker.walk()`:**

1. Начинается с корневого узла дерева
2. Для каждого узла:
   - Вызывается `enterRuleName(ctx)` слушателя (если переопределен)
   - Рекурсивно обходятся все дочерние узлы
   - Вызывается `exitRuleName(ctx)` слушателя (если переопределен)
3. Обход завершается после обработки всех узлов

**Порядок вызова методов для примера:**

Для структуры:
```
{1, {1, {"Папка", 1, 0, "", ""}, {0, {"Шаблон", 0, 0, "", "текст"}}}}
```

Последовательность вызовов:
```
enterFileStructure
  enterRootContent
    enterFolderContent
      enterEntry (folder)
        enterEntry (внутри папки)
          enterEntry (template)
            exitEntry (template)
          exitEntry (template)
        exitEntry (folder)
      exitEntry (folder)
    exitFolderContent
  exitRootContent
exitFileStructure
```

### 2.4. Обработка элементов структуры

**Метод `enterEntry(ctx)` — вход в элемент:**

Этот метод является ключевым для извлечения структуры. Он вызывается при входе в узел `entry`, который может представлять либо папку, либо шаблон.

**Алгоритм работы:**

```python
def enterEntry(self, ctx):
    if ctx.folderHeader():  # Проверка: это папка?
        # Обработка папки
        header = ctx.folderHeader()
        name = header.STRING(0).getText()[1:-1]  # Извлечение имени
        
        new_item = {
            'name': name,
            'type': 'folder',
            'children': []
        }
        
        # Добавление в текущего родителя
        self.current_parent['children'].append(new_item)
        # Обновление стека и текущего родителя
        self.stack.append(new_item)
        self.current_parent = new_item
        
    elif ctx.templateHeader():  # Проверка: это шаблон?
        # Обработка шаблона
        header = ctx.templateHeader()
        name = header.STRING(0).getText()[1:-1]  # Имя шаблона
        # Содержимое шаблона (третий STRING в заголовке)
        content = header.STRING(2).getText()[1:-1] if len(header.STRING()) > 1 else ""
        
        # Добавление шаблона в текущего родителя
        self.current_parent['children'].append({
            'name': name,
            'type': 'template',
            'content': content
        })
```

**Детальный разбор обработки папки:**

1. **Определение типа элемента:**
   ```python
   if ctx.folderHeader():
   ```
   Метод `ctx.folderHeader()` возвращает контекст заголовка папки, если текущий `entry` является папкой, иначе `None`.

2. **Извлечение имени:**
   ```python
   header = ctx.folderHeader()
   name = header.STRING(0).getText()[1:-1]
   ```
   - `header.STRING(0)` получает первый строковый токен (индекс 0) из заголовка
   - `getText()` возвращает текстовое представление токена (с кавычками): `"Папка"`
   - `[1:-1]` удаляет окружающие кавычки: `Папка`

3. **Создание структуры папки:**
   ```python
   new_item = {
       'name': name,
       'type': 'folder',
       'children': []
   }
   ```
   Создается словарь с тремя ключами:
   - `'name'` — имя папки
   - `'type'` — тип элемента (`'folder'`)
   - `'children'` — список дочерних элементов (изначально пустой)

4. **Добавление в иерархию:**
   ```python
   self.current_parent['children'].append(new_item)
   ```
   Новая папка добавляется в список детей текущего родителя.

5. **Обновление стека:**
   ```python
   self.stack.append(new_item)
   self.current_parent = new_item
   ```
   - Папка добавляется в стек для отслеживания вложенности
   - Текущий родитель обновляется на новую папку
   - Все последующие элементы будут добавляться в эту папку

**Детальный разбор обработки шаблона:**

1. **Определение типа элемента:**
   ```python
   elif ctx.templateHeader():
   ```
   Проверка наличия заголовка шаблона.

2. **Извлечение имени и содержимого:**
   ```python
   header = ctx.templateHeader()
   name = header.STRING(0).getText()[1:-1]
   content = header.STRING(2).getText()[1:-1] if len(header.STRING()) > 1 else ""
   ```
   - `STRING(0)` — имя шаблона (первый строковый токен)
   - `STRING(2)` — содержимое шаблона (третий строковый токен, индекс 2)
   - Проверка `len(header.STRING()) > 1` гарантирует наличие содержимого

3. **Создание структуры шаблона:**
   ```python
   self.current_parent['children'].append({
       'name': name,
       'type': 'template',
       'content': content
   })
   ```
   Шаблон добавляется в список детей текущего родителя без изменения стека (так как шаблоны не могут содержать дочерние элементы).

**Метод `exitEntry(ctx)` — выход из элемента:**

```python
def exitEntry(self, ctx):
    if ctx.folderHeader() and len(self.stack) > 1:
        # Для папки: возвращаемся к предыдущему родителю
        self.stack.pop()
        self.current_parent = self.stack[-1]
```

**Алгоритм работы:**

1. **Проверка типа элемента:**
   - Если это папка (`ctx.folderHeader()`) и в стеке больше одного элемента
   - (Проверка `len(self.stack) > 1` предотвращает извлечение корневого элемента)

2. **Возврат к предыдущему уровню:**
   - `self.stack.pop()` удаляет текущую папку из стека
   - `self.current_parent = self.stack[-1]` обновляет текущего родителя на предыдущий элемент

**Пример работы стека:**

Для структуры:
```
Папка1
  ├── Шаблон1
  └── Папка2
      └── Шаблон2
```

Последовательность операций со стеком:

```
1. enterEntry(Папка1)
   stack: [root, Папка1]
   current_parent: Папка1

2. enterEntry(Шаблон1)
   stack: [root, Папка1]  (не изменяется)
   current_parent: Папка1
   → Шаблон1 добавляется в Папка1.children

3. exitEntry(Шаблон1)
   (ничего не происходит, так как это не папка)

4. enterEntry(Папка2)
   stack: [root, Папка1, Папка2]
   current_parent: Папка2
   → Папка2 добавляется в Папка1.children

5. enterEntry(Шаблон2)
   stack: [root, Папка1, Папка2]  (не изменяется)
   current_parent: Папка2
   → Шаблон2 добавляется в Папка2.children

6. exitEntry(Шаблон2)
   (ничего не происходит)

7. exitEntry(Папка2)
   stack.pop() → stack: [root, Папка1]
   current_parent: Папка1

8. exitEntry(Папка1)
   stack.pop() → stack: [root]
   current_parent: root
```

### 2.5. Получение итоговой структуры

**Метод `get_structure()`:**

```python
def get_structure(self):
    return self.stack[0]['children']
```

**Алгоритм:**
- Возвращает список дочерних элементов корневого уровня
- Корневой элемент (`self.stack[0]`) содержит все верхнеуровневые папки и шаблоны
- Результат представляет собой иерархическую структуру вложенных словарей

## 3. Извлечение структуры (файлы, папки, шаблоны)

### 3.1. Формат результирующей структуры

После завершения обхода дерева метод `get_structure()` возвращает список верхнеуровневых элементов. Каждый элемент представляет собой словарь Python со следующей структурой:

**Структура папки:**
```python
{
    'name': str,        # Имя папки
    'type': 'folder',   # Тип элемента
    'children': list    # Список дочерних элементов (папки и шаблоны)
}
```

**Структура шаблона:**
```python
{
    'name': str,          # Имя шаблона
    'type': 'template',  # Тип элемента
    'content': str        # Содержимое шаблона
}
```

### 3.2. Пример извлеченной структуры

**Исходный ST-файл:**
```
{1, {3,
{"СКД", 1, 0, "", ""},
{0, {"Набор данных - Объект", 0, 0, "", ""}},
{1, {"Работа с внешними файлами", 1, 0, "", ""},
{0, {"Работа с Excel", 0, 0, "", ""}},
{0, {"Работа с Word", 0, 0, "", ""}}
}
}}
```

**Результирующая структура:**
```python
[
    {
        'name': 'СКД',
        'type': 'folder',
        'children': [
            {
                'name': 'Набор данных - Объект',
                'type': 'template',
                'content': ''
            }
        ]
    },
    {
        'name': 'Работа с внешними файлами',
        'type': 'folder',
        'children': [
            {
                'name': 'Работа с Excel',
                'type': 'template',
                'content': ''
            },
            {
                'name': 'Работа с Word',
                'type': 'template',
                'content': ''
            }
        ]
    }
]
```

### 3.3. Обработка вложенных структур

Алгоритм корректно обрабатывает произвольную глубину вложенности благодаря механизму стека:

**Пример глубокой вложенности:**
```
Папка1 (уровень 0)
  └── Папка2 (уровень 1)
      └── Папка3 (уровень 2)
          └── Шаблон1 (уровень 3)
```

**Последовательность обработки:**

1. Вход в Папка1 → добавление в стек, `current_parent = Папка1`
2. Вход в Папка2 → добавление в стек, `current_parent = Папка2`
3. Вход в Папка3 → добавление в стек, `current_parent = Папка3`
4. Вход в Шаблон1 → добавление в Папка3.children
5. Выход из Шаблон1 → без изменений
6. Выход из Папка3 → `stack.pop()`, `current_parent = Папка2`
7. Выход из Папка2 → `stack.pop()`, `current_parent = Папка1`
8. Выход из Папка1 → `stack.pop()`, `current_parent = root`

### 3.4. Обработка пустых папок

Пустые папки (без дочерних элементов) корректно обрабатываются грамматикой:

**Правило грамматики:**
```
entry:
    LBRACE int_value ',' folderHeader RBRACE  // Пустая папка
```

**Результат:**
```python
{
    'name': 'ПустаяПапка',
    'type': 'folder',
    'children': []  # Пустой список
}
```

### 3.5. Обработка шаблонов с содержимым

Шаблоны могут содержать произвольный текст в поле `content`:

**Пример:**
```
{0, {"Пример кода", 0, 0, "", "Сообщение = Новый СообщениеПользователю;\nСообщение.Текст = \"Привет\";\nСообщение.Сообщить();"}}
```

**Результат:**
```python
{
    'name': 'Пример кода',
    'type': 'template',
    'content': 'Сообщение = Новый СообщениеПользователю;\nСообщение.Текст = "Привет";\nСообщение.Сообщить();'
}
```

## 4. Преобразование результатов парсинга в структуру данных приложения

### 4.1. Формирование итогового результата

**Метод `parse_st_file()` класса `STFileParserWrapper`:**

```python
def parse_st_file(self, file_path) -> dict:
    try:
        # ... процесс парсинга ...
        
        return {
            'structure': listener.get_structure(),
            'root_name': listener.root_name
        }
    except Exception as e:
        return {
            'structure': [],
            'root_name': os.path.splitext(os.path.basename(file_path))[0]
        }
```

**Структура возвращаемого значения:**

```python
{
    'structure': list,  # Иерархическая структура файла
    'root_name': str     # Имя корневого элемента
}
```

**Компоненты результата:**

1. **`'structure'`** — список верхнеуровневых элементов:
   - Каждый элемент — словарь с ключами `'name'`, `'type'`, `'children'` (для папок) или `'content'` (для шаблонов)
   - Поддерживает произвольную глубину вложенности
   - Сохраняет порядок элементов согласно исходному файлу

2. **`'root_name'`** — имя корневого элемента:
   - Извлекается из имени файла без расширения
   - Используется для идентификации файла в приложении
   - Пример: для файла `МоиШаблоны.st` → `root_name = "МоиШаблоны"`

### 4.2. Обработка ошибок парсинга

**Механизм обработки:**

При возникновении любой ошибки (файл не найден, синтаксическая ошибка, отсутствие зависимостей) метод возвращает безопасную структуру по умолчанию:

```python
except Exception as e:
    return {
        'structure': [],  # Пустая структура
        'root_name': os.path.splitext(os.path.basename(file_path))[0]
    }
```

**Преимущества:**
- Приложение не падает при ошибках парсинга
- Возвращается валидная структура, которую можно обработать
- Имя корня всегда доступно для идентификации файла

### 4.3. Использование структуры в приложении

**Области применения:**

1. **Отображение в пользовательском интерфейсе:**
   - Построение дерева файлов и папок
   - Навигация по структуре
   - Отображение содержимого шаблонов

2. **Модификация структуры:**
   - Добавление новых папок и шаблонов
   - Удаление элементов
   - Переименование элементов
   - Перемещение элементов между папками

3. **Сериализация обратно в ST-файл:**
   - Преобразование структуры Python в формат ST
   - Сохранение изменений в файл
   - Генерация новых ST-файлов

**Пример использования:**

```python
parser = STFileParserWrapper()
result = parser.parse_st_file('example.st')

# Доступ к структуре
structure = result['structure']
root_name = result['root_name']

# Обход структуры
for item in structure:
    if item['type'] == 'folder':
        print(f"Папка: {item['name']}")
        for child in item['children']:
            if child['type'] == 'template':
                print(f"  Шаблон: {child['name']}")
    elif item['type'] == 'template':
        print(f"Шаблон: {item['name']}")
```

### 4.4. Преимущества выбранной структуры данных

**Унифицированный формат:**
- Все элементы (папки и шаблоны) представлены словарями с одинаковой базовой структурой

- Единообразный доступ к свойствам элементов

**Поддержка иерархии:**
- Рекурсивная структура через поле `'children'`

- Простота обхода рекурсивными алгоритмами

**Расширяемость:**
- Легко добавить новые поля в структуру элементов
- Совместимость с JSON для сериализации
- Удобство работы с Python-словарями

**Производительность:**
- Быстрый доступ к элементам по индексу
- Эффективный обход структуры
- Минимальные накладные расходы на преобразование
