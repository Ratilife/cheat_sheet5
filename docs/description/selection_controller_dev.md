# модуль selection_controller.py   **ПЕРЕПИСАТЬ**

в модуле реализован класс TreeSelectionController унаследован от класса QObject библиотеки PySide6.QtCore
Класс TreeSelectionController это контроллер для обработки выделения элементов в дереве.
Получает контект из кэш или модели.

## Основные Сигналы:
    
**content_for_sidepanel = Signal(str, str, str)**   *запрашиваемый данные  в окне с которым работает пользователь*
        - издает сигнал в методе **_process_content()** при работе с деревом в классе **SidePanel**
        - принимает сигнал метод on_display_content в классе  **SidePanel**
        - подключен сигнал в методе _connect_selection_signals() в классе  **SidePanel** и запускается при инициализации
            экземпляра класса
        параметры:
                **content_type**   тип элемента: 'template', 'folder', 'file', 'markdown'
                **content**        Содержимое файла, привязано к типу контента, выводитсяв редактор 
                **path_file**      путь к файлу. Это ключ к кэш 
    
**content_for_editor = Signal(str, str, str)** *запрашиваемый данные  в окне с которым работает пользователь*
        - издает сигнал в методе **_process_content()** при работе с деревом в классе **FileEditorWindow**
        - принимает сигнал метод on_display_content() в классе  **FileEditorWindow** 
        - подключен сигнал в методе _connect_selection_signals() вклассе  **FileEditorWindow** и запускается при инициализации
            экземпляра класса        
        параметры:
                **content_type**   тип элемента: 'template', 'folder', 'file', 'markdown'
                **content**        Содержимое файла, привязано к типу контента, выводитсяв редактор 
                **path_file**      путь к файлу. Это ключ к кэш 

**selection_changed = Signal(dict)**   выбранный параметр изменен (Сигнал о изменении выделения)
        - издает сигнал в методе _handle_selection()  в классе **TreeSelectionController**
        - принимает сигнал метод selection_changed() в классе **FileEditorWindow**
        -подключен сигнал к методу _connect_selection_signals() класс **FileEditorWindow**
        - принимает сигнал  метод on_update_selection_status() класса **SidePanel**
        - подключен сигнал к методу _connect_selection_signals класса **SidePanel**

**error_occurred = Signal(str)**  # error_message       произошла ошибка

        - принимает сигнал метод on_show_selection_error()  в классе **SidePanel**
        -подключен сигнал в методе _connect_selection_signals() в классе  **SidePanel** и запускается при инициализации
            экземпляра класса
**content_for_element = Signal(str, str, str, dict)**  # type, element_content, path, element_info
        *Еще не описан*

## Конструктор:
**Сигнатура:** `__init__(content_cache, parent=None)`
### **Параметры:**
    *   `content_cache`: **Обязательный.** Объект, предоставляющий доступ к кэшированному содержимому файлов. Ожидается, что он реализует метод `get(path)`.
    *   `parent` (`QObject`, опционально): Родительский объект в иерархии Qt.

*Важность: Без корректного объекта кэша функциональность извлечения контента будет ограничена только данными, непосредственно хранящимися в элементах дерева.*

### *Инициализация атрибутов*:
`super().__init__(parent)` - родительский конструктор
`self.content_cache` - Прямое сохранение переданного параметра `content_cache`
    - Назначение: Делает кэш контента доступным для всех методов класса
    - Использование: используется в методе _extract_content() для резервного получения контента

`self.current_source` - отслеживает активный источник (дерево), к которому подключен контроллер в данный момент
    `это переменная-идентификатор, которая отслеживает, к какому именно дереву (источнику выборки) подключен контроллер в данный момент. Она решает фундаментальную проблему маршрутизации: "Куда отправить контент, если контроллер может работать с несколькими деревьями?"`
    - Тип: строка `str`
    - Начальное значение: Пустая строка ''
    - Жизненный цикл:
        • Инициализация пустой строки 
        • Устанавливается в `connect_tree_view()` при подключении к дереву
        • Используется в `_process_content()` для определения направления маршрутизации контента
    *Важность: Критически важен для корректной работы системы маршрутизации контента*
    **Практические задачи** (*примеры возможного использования*):
        - Маршрутизация контента к разным получателям
          ` есть два дерева — одно в боковой панели, другое в редакторе. При клике на элемент нужно отправлять контент в разные места`
```python
# Подключаем контроллер к разным деревьям
controller.connect_tree_view(sidepanel_tree, 'sidepanel')
                controller.connect_tree_view(editor_tree, 'editor')
                # Внутри _process_content:
                if self.current_source == 'sidepanel':
                # Отправляем в боковую панель для предпросмотра
                self.content_for_sidepanel.emit(...)
                elif self.current_source == 'editor':
                # Отправляем в редактор для редактирования
                self.content_for_editor.emit(...)
```     
        - Разное поведение для разных источников
          `Для боковой панели нужен только предпросмотр, а для редактора — полный контент с возможностью редактирования.`
```python
def _process_content(self, metadata, item, source_name):
    content = self._extract_content(metadata, item)
    
    if source_name == 'sidepanel':
        # Для боковой панели - ограниченный предпросмотр
        preview = content[:500] + "..." if len(content) > 500 else content
        self.content_for_sidepanel.emit(metadata['type'], preview, metadata.get('path', ''))
    
    elif source_name == 'editor':
        # Для редактора - полный контент
        self.content_for_editor.emit(metadata['type'], content, metadata.get('path', ''))
```
        - Разная логика обработки ошибок
          `В редакторе ошибки должны быть более детальными, в боковой панели — краткими.` 
```python
def _handle_selection(self, index):
    try:
        # основная логика...
    except Exception as e:
        if self.current_source == 'editor':
            self.error_occurred.emit(f"Ошибка редактора: {str(e)}")
        else:
            self.error_occurred.emit("Не удалось загрузить контент")
```
        - Ведение журнала действий
          ` Нужно логировать, из какого источника пришел запрос для аналитики`
```python
def _handle_selection(self, index):
    print(f"Обработка выбора из источника: {self.current_source}")
    # основная логика...
```
        - Приоритизация запросов
          `Если контроллер обрабатывает запросы от нескольких источников, можно реализовать приоритеты.`
```python
def connect_tree_view(self, tree_view, source_name, priority=1):
    self.current_source = source_name
    self.current_priority = priority  # Добавляем приоритет
```

## Методы:

`connect_tree_view(tree_view, source_name)`
    Подключает контроллер к сигналу `clicked` древовидного представления.
**Параметры:**
        `tree_view`: **Обязательный.** Объект древовидного представления (например, `QTreeView`), который имеет сигнал `clicked`(унаследованный от QAbstractItemView).
        `source_name` (`str`): **Обязательный.** Уникальный идентификатор источника, который определяет, куда будет направлен контент (например, `'sidepanel'` или `'editor'`).
            *Важность: Это значение сохраняется в self.current_source и используется throughout всем жизненным циклом обработки выделения*
**Исключения:**
        Не выбрасывает явных исключений, но в случае ошибки излучает сигнал `error_occurred`, если переданный `tree_view` не поддерживает сигнал `clicked`.
**Назначение и роль в архитектуре**
        1. Метод служит точкой входа для интеграции контроллера с пользовательским интерфейсом. Он решает следующие ключевые задачи:
        2. Установка соединения между сигналом клика дерева и слотом обработки контроллера
        3. Идентификация источника выборки для корректной маршрутизации контента
        4. Валидация совместимости переданного дерева с ожидаемым интерфейсом
        5. Активация контекста выполнения для последующих операций
**Используется в проекте**
        в методах:
            connect_tree_views() класс **TreeModelManager**  `self.cselection_controller.connet_tree_view(tree_view,"editor")`
            _create_tabs_with_trees() класс **SidePanel**    `self.tree_model_manager.selection_controller.connect_tree_view(tree_view, "sidepanel")`
            _setup_managers() класс **FileEditorWindow**     `self.tree_model_manager.selection_controller.connect_tree_view(tree_view, "editor")`
**Краткое описание:**
```python
    
        self.current_source = source_name  # Запоминаем источник
        #Запоминаем, какой источник связан с текущим деревом, чтобы позже (например, при обработке клика) можно было корректно реагировать на действия пользователя в зависимости от этого источника       
```    
```python
            if hasattr(tree_view, 'clicked'):
            tree_view.clicked.connect(self._handle_selection)
            # проверяем имеет ли объект tree_view атрибут (или свойство) с именем 'clicked'.
            # При прохождении проверки запускаем метод _handle_selection() из клпсса TreeModelManager
            # если проверка нае прошла запускаем сигнал об ошибке
```        
        hasattr(obj, name) — это встроенная функция Python, которая возвращает True, 
            если у объекта obj есть атрибут или метод с именем name (передаётся как строка), и False — если нет.


`_handle_selection(self, index)`
    Приватный слот, который является центральным обработчиком событий выделения в дереве. Метод запускается автоматически при каждом клике пользователя на элемент дерева и координирует весь процесс: от извлечения сырых данных из модели до формирования структурированных метаданных и запуска обработки контента.
    определяется как тип Слот, потому что,подключается к сигналу clicked дерева
**Параметры**:
        `index: QModelIndex` - Объект Qt, содержащий информацию о выбранном элементе в древовидной модели.
           **Структура данных**: Содержит:
            Ссылку на модель данных (index.model())
            Ссылку на внутренний объект элемента (index.internalPointer())
            Информацию о строке, колонке и родительских отношениях
            **Особенности**: Может быть невалидным (например, при клике на пустую область дерева)
            **Источник**: Передается автоматически из сигнала clicked дерева виджетов 
    Побочные эффекты: Излучает сигналы selection_changed и (опционально) error_occurred
**Исключения**
        - Ловит все исключения: Метод обернут в try-except блок для предотвращения падения приложения
        - Обработка ошибок: Любое исключение преобразуется в сигнал error_occurred с текстом ошибки
        - Гарантия безопасности: Метод никогда не пробрасывает исключения наружу
**Краткое описание:**
**Проверка наличия входных данных**
```python
            if not index.isValid():
                self.selection_changed.emit({'has_selection': False})
                return  
```        
    - Проверяет, представляет ли индекс реальный элемент дерева
    - Если индекс невалиден (клик мимо элемента), излучает сигнал сброса выделения
    - Завершает выполнение метода досрочно

**Извлечение данных из модели**
```python
model = index.model()               # Получаем модель дерева
item = index.internalPointer()      # Получаем объект элемента
```
*Компоненты:*
    `model`: Ссылка на объект модели данных (например, QFileSystemModel или кастомная модель)
    `item`: Внутренний объект элемента, содержащий бизнес-логику и данные

**Формирование метаданных**
```python
metadata = {
    'type': model.data(index, Qt.UserRole + 2),  # 'markdown', 'template' и т.д.
    'name': model.data(index, Qt.DisplayRole),   # Имя файла/папки
    'path': self._get_file_path_for_item(item),  # Ищем путь через объект item
    'has_selection': True
}
```
*Структура метаданных:*
| Ключ           | Значение               | Источник                    | Назначение                                |
|----------------|------------------------|-----------------------------|-------------------------------------------|
| `type`         | `str`                  | `Qt.UserRole + 2`           | Определяет тип контента для обработки     |
| `name`         | `str`                  | `Qt.DisplayRole`            | Отображаемое имя элемента                 |
| `path`         | `str` или `None`       | `_get_file_path_for_item()` | Физический путь к файлу                   |
| `has_selection`| `bool` (всегда `True`) | -                           | Флаг наличия валидного выделения          |

**Уведомление о изменении выделения**
```python
    self.selection_changed.emit(metadata)
```
**Назначение:** Информирует подписчиков о факте изменения выделения
**Получатели:** Обычно компоненты UI, которые должны обновиться при смене выбора

**Запуск обработки контента (для поддерживаемых типов)**
    *Условия обработки:*
        - Только для типов `'markdown'` и `'template'`
        - Использует заранее установленный `self.current_source` для маршрутизации

**Обработка ошибок**
```python
except Exception as e:
    self.error_occurred.emit(f"Selection error: {str(e)}")
```
**Стратегия:** Преобразование технических исключений в пользовательские сообщения об ошибках

**Зависимости от других методов**
`_get_file_path_for_item(item)`
- **Вызывается в:** Фазе 3 (формирование метаданных)
- **Назначение:** Определяет физический путь к файлу через анализ иерархии элементов
- **Критичность:** Высокая — без корректного пути невозможна загрузка контента

`_process_content(metadata, item, source_name)`
- **Вызывается в:** Фазе 5 (обработка контента)
- **Условия вызова:** Только для поддерживаемых типов элементов
- **Назначение:** Запускает цепочку извлечения и маршрутизации контента

**Внешние зависимости**
- **Модель данных:** Должна предоставлять данные для ролей `Qt.DisplayRole` и `Qt.UserRole + 2`
- **Объекты элементов:** Должны иметь атрибут `item_data` с определенной структурой
- **Родительская иерархия:** Должна быть доступна через `parent_item`
**Используется в проекте**
    В методе: connect_tree_view() класс **TreeSelectionController**

`_get_file_path_for_item(self, item)`
    Приватный вспомогательный метод, который рекурсивно определяет физический путь к файлу, ассоциированному с элементом дерева. Основная сложность заключается в том, что путь может храниться не в самом элементе, а в его родителях, причем логика поиска различается для разных типов элементов.
    Тип: Вспомогательный метод навигации по иерархии
**Параметры**
    item: object
        Назначение: Внутренний объект элемента древовидной модели
        Ожидаемая структура: Должен иметь атрибуты:
        `item_data: list` - список данных элемента определенной структуры.  Структура item_data: `[Имя, Тип, Контент]` 
        `parent_item: object` - ссылка на родительский элемент (опционально)
        *Важность: Корректность работы метода полностью зависит от структуры этого объекта*
**Возвращаемое значение**  
    Тип: Optional[str]
    Успех: Строка с абсолютным или относительным путем к файлу
    Неудача: None - если путь не найден в цепочке родителей
**Детальный алгоритм работы**
**Обработка элементов типа markdown**
```python
if (hasattr(item, 'item_data') and
        len(item.item_data) > 1 and
        item.item_data[1] == 'markdown'):
            parent_item = getattr(item, 'parent_item', None)  # Получаем родителя
            if (parent_item and
                    hasattr(parent_item, 'item_data') and
                    len(parent_item.item_data) > 2):
                return parent_item.item_data[2]
```
*Особенность: Для markdown-элементов путь всегда ищется у непосредственного родителя, а не у самого элемента.*

1. **Проверка элемента:** Убеждается, что элемент действительно является markdown
2. **Поиск родителя:** Получает parent_item через getattr(item, 'parent_item', None)
3. **Извлечение пути:** Если родитель существует и имеет корректные item_data, берет путь из parent_item.item_data[2]
4. **Возврат результата:** Возвращает путь или None

**Обработка других типов элементов (file, folder и т.д.)**
```python
current_item = item
        while current_item:
            if (hasattr(current_item, 'item_data') and
                    len(current_item.item_data) > 1 and
                    current_item.item_data[1] in ['file'] and
                    len(current_item.item_data) > 2):
                return current_item.item_data[2]
```
Рекурсивный подъем по иерархии родителей до первого найденного элемента типа file.

1. **Инициализация:** Начинает с текущего элемента
2. **Цикл поиска:** Поднимается по цепочке parent_item пока не достигнет корня
3. **Критерий остановки:** Находит первый элемент с типом file и непустым путем
4. **Возврат результата:** Возвращает найденный путь или None если достигнут корень

**Проверки безопасности**
    Метод включает многоуровневые проверки для предотвращения ошибок:
    `hasattr(current_item, 'item_data')`- защита от некорректных объектов
    `len(item.item_data) > N` - защита от выхода за границы списка
    `getattr(item, 'parent_item', None)` - безопасное получение родителя

Зависимости и взаимодействия
Зависимости от структуры данных
    **Модель дерева:** Должна создавать элементы с атрибутами item_data и parent_item
    **Формат item_data:** Должен соответствовать ожидаемой структуре [index, type, path, ...]
    **Типы элементов:** Должны включать 'markdown' и 'file' для корректной работы

**Используется в проекте**
    используется в методе: _handle_selection() класса **TreeSelectionController**

`_process_content(metadata, item, source_name)`
Приватный метод-оркестратор, который управляет всем процессом обработки контента после успешного выделения элемента. Метод координирует извлечение контента из различных источников, выполняет валидацию данных и осуществляет интеллектуальную маршрутизацию контента к соответствующим потребителям на основе идентификатора источника.

**Параметры**
`metadata: dict`
Словарь с метаданными выбранного элемента, сформированный в _handle_selection()
Обязательная структура:
```python
{
    'type': str,           # Тип контента: 'markdown', 'template', etc.
    'name': str,           # Отображаемое имя элемента
    'path': Optional[str], # Путь к файлу (может быть None)
    'has_selection': bool  # Всегда True
}
```
Критичность: Высокая - без корректных метаданных обработка невозможна

`item: object`
**Назначение:** Внутренний объект элемента дерева для прямого доступа к данным
**Использование:** Передается в _extract_content() для извлечения контента
**Структура:** Должен иметь атрибут item_data с данными элемента

`source_name: str`
**Назначение:** Идентификатор источника, определяющий направление маршрутизации контента
**Допустимые значения:** 'sidepanel', 'editor'
**Важность:** Критический параметр, влияющий на выбор сигнала для отправки

**Детальный алгоритм работы**

**Проверка входных параметров**
```python
# Валидация метаданных
if not metadata or not isinstance(metadata, dict):
    self.error_occurred.emit("Неверные метаданные элемента")
    return

# Валидация источника
if source_name is None:
    self.error_occurred.emit("Не указан источник для обработки контента")
    return
```
Защита от некорректных данных на самом начале выполнения
    Критерии:
        metadata должен быть непустым словарем
        source_name не должен быть None
**Извлечение контента**
```python
content = self._extract_content(metadata, item)
if content is None:
    self.error_occurred.emit(f"Контент недоступен для {metadata['name']}")
    return
```
**Процесс:** Делегирует фактическое извлечение специализированному методу _extract_content()
**Обработка ошибок:** Если контент недоступен, метод завершается с ошибкой

**Валидация источника маршрутизации**
```python
if source_name not in ['sidepanel', 'editor']:
    self.error_occurred.emit(f"Неизвестный источник: {source_name}")
    return
```
**Назначение:** Гарантирует, что контент будет отправлен только в поддерживаемые направления
**White-list подход:** Только явно разрешенные источники принимаются

**Маршрутизация контента**
```python
if source_name == "sidepanel":
    self.content_for_sidepanel.emit(metadata['type'], content, metadata.get('path', ''))
elif source_name == "editor":
    self.content_for_editor.emit(metadata['type'], content, metadata.get('path', ''))
```
**Логика ветвления:** На основе source_name выбирается соответствующий сигнал
**Данные сигнала:** Передается полный набор информации для потребителя

**Структура передаваемых данных**
`content_for_sidepanel.emit(content_type, content, path_file)` и `content_for_editor.emit(content_type, content, path_file)`
`content_type`	`str`	`metadata['type']`	        Определяет тип контента для отображения
`content`	    `str`	                            Извлеченный контент	Непосредственное содержимое для показа
`path_file`	    `str`	`metadata.get('path', '')`	Путь для идентификации и навигации

Особенности данных:
`path_file` извлекается безопасно с fallback на пустую строку
`content_type` наследуется напрямую из метаданных
`content` проходит полный цикл извлечения и валидации

Зависимости:
`_extract_content(metadata, item)`

    Роль: Поставщик контента
    Ожидаемый результат: str или None
    Критичность: Высокая - без контента дальнейшая обработка невозможна
    Внешние сигналы (используются как выходы):

**`_extract_content(metadata, item)`**
Приватный метод-стратег, который реализует многоуровневую стратегию извлечения контента из различных источников. Метод действует по принципу "водопада" (waterfall) — последовательно проверяет доступные источники контента от наиболее быстрого к наиболее надежному, возвращая первый успешный результат.
**Параметры**
`metadata: dict`
Назначение: Словарь метаданных элемента, используется для доступа к пути файла
Ключевые поля:
    `path`: `Optional[str]` - путь к файлу для доступа к кэшу
    `type`: `str` - тип элемента (информационно)
    `name`: `str` - имя элемента (информационно)
    Важность: Критичен для доступа к кэшированному контенту

`item: object`
Назначение: Непосредственный объект элемента дерева для прямого доступа к данным
Критичность: Основной источник "горячих" данных

**Возвращаемое значение**
    **Тип**: Optional[str]
    **Успех**: Строка с содержимым элемента
    **Неудача**: None - если контент недоступен во всех источниках
    **Особенности**: Может возвращать пустую строку "" как валидный контент

**Детальный алгоритм работы**
**Прямой доступ к данным элемента (Наивысший приоритет)**
```python
# 1. Пробуем из данных элемента
if len(item.item_data) > 2 and item.item_data[2]:
    return item.item_data[2]
```
**Логика**: Проверяет, содержится ли контент непосредственно в объекте элемента
Условия успеха:
`item.item_data` имеет как минимум 3 элемента
`item.item_data[2]` не является None, False или пустой строкой
**Преимущество**: Максимальная производительность (прямой доступ к памяти)
Недостаток: Данные могут быть устаревшими

**Доступ через кэш контента (Средний приоритет)**
```python
# 2. Пробуем из кэша (если есть путь)
elif self.content_cache and metadata.get('path'):
    cached_data = self.content_cache.get(metadata['path'])
    if cached_data:
        return cached_data.get('content', '') if isinstance(cached_data, dict) else str(cached_data)
```
Логика: Если прямой доступ невозможен, обращается к системе кэширования
Условия успеха:
    Кэш инициализирован `(self.content_cache is not None)`
    В метаданных есть валидный путь `(metadata.get('path'))`
    Кэш содержит данные для этого пути
    **Обработка форматов**: Поддерживает как простые строки, так и словари с контентом

**Контент недоступен (Фallback)**
```python
# 3. Контент не найден
return None
```
**Логика**: Все источники исчерпаны, контент недоступен
**Результат**: Явное указание на отсутствие данных

Взаимодействие с другими компонентами
Зависимости:
`self.content_cache`
    Тип: object с методом get(key)
    Роль: Вторичный источник данных
    Критичность: Условная - метод работает и без кэша

`item.item_data`
    Структура: list с минимум 3 элементами
    Роль: Первичный источник данных
    Критичность: Высокая - основной канал получения "свежих" данных

`_process_content()` - единственный потребитель этого метода
Вызывается только когда требуется извлечение контента для поддерживаемых типов
