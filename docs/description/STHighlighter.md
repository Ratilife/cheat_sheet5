## кэш класса
```python
    _tokens_by_line = {}  
```
 dict['int' номер строки , dict[
                            'start':позиция в исходной строке (для отладки) `token.column`,
                            'length':длина текста токена `len(token.text)`,
                            'type':тип токена (например, 'IDENTIFIER', 'KEYWORD') `token_type`, 
                            'text':сам текст токена (например, 'Функция', 'Тест') `token.text` ]]
 `'start': token.column`
**Что это:** Позиция, где токен начинался в оригинальной строке, полученная из ANTLR-лексера.
**Зачем:** Это приблизительная позиция, которая может использоваться как подсказка при поиске токена в изменённой строке.
**Пример:** Если токен Тест был на позиции 7, и пользователь добавил Новая перед ним, то реальная позиция стала 12. Но мы можем начать искать Тест около позиции 7, а не с начала строки — это оптимизирует поиск.

`'length': len(token.text)`
**Что это:** Длина текста токена (в символах).
**Зачем:** Нужна для вызова self.setFormat(start, length, fmt) — чтобы Qt знал, сколько символов подсветить.
**Пример:** token.text = "Тест" → length = 4 → setFormat(14, 4, fmt) подсветит 4 символа, начиная с позиции 14.

`'type': token_type`
**Что это:** Строковое имя типа токена (например, 'IDENTIFIER', 'PROCEDURE_KEYWORD', 'STRING').
**Зачем:** Нужно для определения цвета и стиля подсветки. Ты используешь type, чтобы найти цвет в self.color_map[lang][type].
**Пример:** 'type': 'PROCEDURE_KEYWORD' → color = self.color_map['1c']['PROCEDURE_KEYWORD'] → fmt.setForeground(QColor('red')).

`'text': token.text`
**Что это:** Фактический текст токена, как его распознал лексер.
**Зачем:** Ключевой элемент для поиска токена в текущем тексте строки, потому что:
- Он не меняется при редактировании.
- Мы можем найти его в currentBlock().text() и узнать реальную позицию.
**Пример:** 'text': 'Тест' → ищем "Тест" в строке "Функция НоваяТест()" → находим на позиции 14.

## Методы:
### `_apply_token_format(self, token_start, token_length, token_type, token_text, lang: str)`
1. Получаем текущий текст строки.
```python
    current_line_text = self.currentBlock().text()
```
- `self.currentBlock()` — возвращает текущий блок текста (в Qt текст в редакторе разбит на блоки, обычно по строкам).
- `.text()` — получает текст этого блока (то есть текущей строки).
Сохраняем его в переменную `current_line_text`.
```text
Пример:
Если строка в редакторе выглядит так:
Функция Тест(Парам) Экспорт,
то current_line_text будет равен этой строке.
```
2. Ищем токен в текущем тексте строки

```python
    actual_start = current_line_text.find(token_text, max(0, token_start))
```
- `token_text` — это текст токена, который нужно подсветить (например, "Функция").
- `token_start` — ожидаемая позиция, с которой должен начинаться токен (например, 0).
- `find(...)` — ищет token_text в current_line_text, начиная с позиции max(0, token_start) (не может быть отрицательной).
*Результат — **реальная позиция** токена в строке, или -1, если не найден.*
**Зачем?**
Потому что `token_start` может быть приблизительным (например, из ANTLR), и токен может находиться не точно в этой позиции из-за табуляций, пробелов и т.п.

3. Проверяем, нашли ли токен
```python
    if actual_start != -1:  # нашли токен в строке
```
Если `find` вернул -1, значит токен не найден в строке.
Тогда `ничего не делаем`, метод завершает работу.

4. Создаём формат (цвет)
```python
   fmt = QTextCharFormat() 
```
- `QTextCharFormat` — это объект, который хранит **форматирование текста**: цвет, жирность, курсив и т.д.
- Создаём пустой формат, чтобы потом его настроить.

5. Получаем цвет для типа токена
```python
   color_name = self.color_map.get(lang, {}).get(token_type) 
```
lang — язык (например, '1c').
token_type — тип токена (например, 'FUNCTION_KEYWORD').
self.color_map — словарь, где хранятся цвета для каждого типа токена.
.get(...) — безопасно возвращает цвет, если он есть, иначе None.
```text
    Пример:
    Если lang='1c' и token_type='FUNCTION_KEYWORD', то color_name может быть 'red'.
```
6. Устанавливаем цвет текста
```python
    if color_name:
        fmt.setForeground(QColor(color_name))
```
Если цвет найден (`color_name` не `None`), то:
    - `QColor(color_name)` — создаёт Qt-цвет (например, QColor('red')).
    - `.setForeground(...)` — устанавливает **цвет текста** (а не фона).
Теперь `fmt` содержит цвет, который нужно применить.

7. Применяем формат к найденной позиции

```python
    self.setFormat(actual_start, token_length, fmt)
```
- `actual_start` — реальная позиция, с которой начинается токен в строке.
- `token_length` — длина токена (например, длина слова Функция — 7).
- `fmt` — формат (цвет), который нужно применить.
- `self.setFormat(...)` — применяет формат к участку строки от `actual_start` длиной `token_length`.

Результат:
Слово Функция будет подсвечено нужным цветом (например, красным).

**Итого:**
Метод:
*Находит текст текущей строки.*
*Ищет в ней нужный токен.*
*Если находит — применяет к нему цвет, соответствующий его типу (например, FUNCTION_KEYWORD — красный).*
*Изменяет отображение в редакторе.*
*Это позволяет подсвечивать синтаксис (ключевые слова, переменные, строки и т.д.) в редакторе кода.*

### `_on_document_changed(self, position: int, removed: int, added: int)`
Этот **метод автоматически вызывается**, когда в текстовом редакторе пользователь **вводит, удаляет или изменяет** текст. Qt (библиотека интерфейса) передаёт ему три параметра:
`position` — позиция, где началось изменение (например, символ 50 в тексте).
`removed` — сколько символов было удалено (например, 0, если только добавили).
`added` — сколько символов было добавлено (например, 3, если ввели слово abc).

1. Получаем документ
```python
    doc = self.document()
```
- `self.document()` — возвращает текстовый документ, с которым работает подсветка (всё содержимое редактора).
- Сохраняем его в переменную `doc`.

2. Проверяем, есть ли документ
```python
    if not doc:
        return
```
- Если `doc` равен `None` (документа нет), **прекращаем выполнение метода**.
Это **безопасная проверка**, чтобы не вызвать ошибку дальше.

3. Находим начальную строку, затронутую изменением
```python
   affected_start_line = doc.findBlock(position).blockNumber() + 1 
```
- `doc.findBlock(position)` — находит **блок (строку)**, в котором находится **символ** на позиции `position`.
- `.blockNumber()` — возвращает **номер блока (строки), начиная с 0**.
- Прибавляем 1, чтобы получить **обычный номер строки**, как в редакторе (начиная с 1).
```text
    Пример:
    Если position = 10, и символ 10 находится в строке 3, то affected_start_line = 3.
```

4. Находим конечную строку, затронутую изменением
```python
    affected_end_line = doc.findBlock(position + added).blockNumber() + 1
```
- `position + added` — позиция **после вставленного текста**.
- `doc.findBlock(...)` — находит **блок (строку)**, в котором находится **последний символ изменённой области**.
- `.blockNumber() + 1` — получаем **номер строки**, начиная с 1.
```text
    Пример:
    Если position = 10, added = 5, то position + added = 15.
    Если символ 15 находится в строке 4, то affected_end_line = 4.
```

5. Цикл по затронутым строкам
```python
    for line_num in range(affected_start_line, affected_end_line + 1):
```
- `range(...)` — создаёт список номеров строк от `affected_start_line` до `affected_end_line` включительно.
- Цикл будет проходить по каждой строке, которая изменилась.
```text
Пример:
Если affected_start_line = 3, affected_end_line = 5, то line_num будет: 3, 4, 5.
```
6. Перестраиваем токены для строки
```python
    self._rebuild_line_tokens(line_num)
```
- Вызываем **вспомогательный метод**, который **пересчитывает токены** (например, ключевые слова, переменные) **только в одной строке**.
- Это **экономит время**, потому что не нужно пересчитывать **весь документ**.

**Итого:**
*Метод:*
*Узнаёт, где произошло изменение в тексте.*
*Находит начальную и конечную строки, которые затронуты.*
*Пересчитывает синтаксис (токены) только в этих строках, а не во всём документе.*
*Это позволяет быстро и эффективно обновлять подсветку синтаксиса при каждом изменении текста.*

### `_rebuild_line_tokens(self, line_number: int)`

Этот метод **пересчитывает токены** (например, ключевые слова, переменные, строки) **только для одной строки** в тексте. Это нужно, чтобы **не пересчитывать весь документ**, когда изменилась только одна строка.

1. Получаем документ
```python
    doc = self.document()
```
- `self.document()` — возвращает текстовый документ, с которым работает подсветка.
- Сохраняем его в переменную `doc`.

2. Проверяем, есть ли документ и корректен ли номер строки

```python
    if not doc or line_number < 1 or line_number > doc.blockCount():
        return
```
- `not doc` — если документа нет, **ничего не делаем**.
- `line_number < 1` — если номер строки **меньше 1, некорректный номер**.
- `line_number > doc.blockCount()` — если номер строки **больше**, чем **всего строк в документе, некорректный номер**.
- Если хотя бы одно из условий истинно — **метод завершает работу**.
**Зачем?**
Чтобы **не пытаться обработать строку**, которой **не существует**.

3. Получаем блок (строку) по номеру
```python
    block = doc.findBlockByNumber(line_number - 1)
```
- `doc.findBlockByNumber(...)` — ищет блок (строку) по номеру.
- Qt нумерует блоки с 0, а мы передаём номер строки с 1, поэтому вычитаем 1.
- Сохраняем блок в переменную `block`.

4. Проверяем, корректен ли блок
```python
    if not block.isValid():
        return
```
`block.isValid()` — проверяет, **существует ли блок**.
Если **нет, метод завершает работу**.

5. Получаем текст строки
```python
    line_text = block.text()
```
- `.text()` — возвращает текст текущего блока (то есть строки).
- Сохраняем его в переменную `line_text`.

6. Если строка пустая — удаляем её из кэша
```python
    if not line_text.strip():
        if line_number in self._tokens_by_line:
            del self._tokens_by_line[line_number]
        return
```
- `line_text.strip()` — убирает пробелы в начале и конце строки.
- `if not ...` — если строка пустая или содержит только пробелы:
  - Проверяем, есть ли запись о токенах для этой строки в кэше.
  - Если есть — удаляем её.
  - Метод завершает работу.
**Зачем?**
  Если строка пустая, токены в ней не нужны, и их можно удалить из кэша, чтобы не тратить память.

7. Лексируем только эту строку
```python
    input_stream = InputStream(line_text)
```
- `InputStream(...)` — создаёт входной поток из текста строки.
- Это вход для лексера (он будет "читать" текст и делить его на токены).

8. Создаём лексер
```python
    lexer = BSLLexer(input_stream)
```
- `BSLLexer(...)` — это лексер для языка 1С (BSL).
- Он разбивает текст строки на токены (например, Функция, Перем, Истина, +, ( и т.д.).

9. Убираем стандартные обработчики ошибок
```python
    lexer.removeErrorListeners()
```
- Убирает **встроенные обработчики ошибок**, чтобы не мешали работе.

10. Добавляем "тихий" обработчик ошибок
```python
    lexer.addErrorListener(IgnoreErrorListener())
```
- `IgnoreErrorListener()` — своё правило, что ошибки лексирования игнорируются.
- Это позволяет продолжить работу, даже если строка содержит некорректный синтаксис.

11. Создаём список для токенов
```python
    tokens = []
```
- `tokens` — список, в который будем складывать токены строки.

12. Получаем первый токен
```python
    token = lexer.nextToken()
```
- `.nextToken()` — возвращает **следующий токен** из строки.
- В данном случае — **первый токен**.

13. Цикл: проходим по всем токенам строки
```python
    while token.type != Token.EOF:
```
- `Token.EOF` — специальный токен, который означает `конец текста`.
- Цикл будет `работать`, пока `не дойдёт до конца строки.`

14. Получаем тип токена

```python
    token_type = self._get_token_type(token, lexer, {})
```
- `self._get_token_type(...)` — вспомогательный метод, который определяет тип токена.
    - Например, IDENTIFIER, FUNCTION_KEYWORD, STRING, и т.д.
- Возвращает **символьное имя токена.**

15. Проверяем, есть ли у токена тип и он не ошибочный
```python
    if token_type and token_type != '<INVALID>':
```
- `token_type` — должен быть не пустым.
- `!= '<INVALID>'` — не должен быть ошибочным.

16. Добавляем токен в список
```python
    tokens.append({
    'start': token.column,
    'length': len(token.text),
    'type': token_type,
    'text': token.text
    })
```
- `.append(...)` — добавляет словарь с информацией о токене в список tokens.
- `'start'` — позиция токена в строке (например, 0).
- `'length'` — длина токена (например, 7 для слова Функция).
- `'type'` — тип токена (например, FUNCTION_KEYWORD).
- `'text'` — текст токена (например, Функция).

17. Переходим к следующему токену
```python
    token = lexer.nextToken()
```
- Получаем следующий токен из строки.

18. Обновляем кэш для этой строки
```python
    if tokens:
        self._tokens_by_line[line_number] = tokens
```
- Если токены были найдены:
    - Сохраняем их в кэш по номеру строки.

19. Если токенов нет — удаляем запись из кэша
```python
    else:
    if line_number in self._tokens_by_line:
        del self._tokens_by_line[line_number]
```
Если токенов не было:
- Проверяем, есть ли запись о токенах для этой строки в кэше.
- Если есть — удаляем её.

**Итого:**
*Метод:*
*Получает текст одной строки.*
*Разбивает её на токены (например, Функция, Перем, +).*
*Сохраняет токены в кэш, чтобы не пересчитывать снова.*
*Если строка пустая или токенов нет — удаляет старые данные из кэша.*
*Это очень эффективно, потому что не пересчитывает весь документ, а только одну строку.*

### `_rebuild_tokens_cache(self)`
Этот метод полностью пересчитывает токены (например, ключевые слова, переменные, строки) для всего документа. Это нужно, когда:
- изменяется язык (например, с Python на 1С),
- меняется текст документа (например, пользователь вставил много строк),
- или нужно обновить подсветку полностью.

1. Сбрасываем кэш токенов
```python
    self._tokens_by_line = {}
```
- `self._tokens_by_line` — это словарь, в котором хранятся токены для каждой строки.
- `= {}` — очищаем его, то есть удаляем все старые токены.
- Теперь кэш пустой.
**Зачем?**
Потому что мы будем пересчитывать всё заново, и старые данные больше не нужны.

2. Проверяем, установлен ли язык
```python
    if not self.language or self.language != '1c':
        return
```
- `self.language` — текущий язык подсветки (например, '1c', 'python').
- Если язык не установлен (not self.language) или не равен '1c':
- метод завершает работу, потому что токены нужно пересчитывать только для 1С.
**Зачем?**
Потому что лексер BSLLexer работает только с 1С, и для других языков он не подходит.

3. Получаем документ
```python
    doc = self.document()
```
- `self.document()` — возвращает текстовый документ, с которым работает подсветка.
- Сохраняем его в переменную `doc`.

4. Проверяем, есть ли документ и не пустой ли он
```python
    if not doc or not doc.toPlainText().strip():
        return
```
- `not doc` — если документа нет, ничего не делаем.
- `doc.toPlainText()` — возвращает весь текст документа.
- `.strip()` — убирает пробелы в начале и в конце.
- `not ...` — если текст пустой:
метод завершает работу, потому что нечего лексировать.

5. Цикл: перестраиваем каждую строку
```python
    for line_num in range(1, doc.blockCount() + 1):
```
- `doc.blockCount()` — возвращает количество строк в документе.
- `range(1, doc.blockCount() + 1)` — создаёт список номеров строк от 1 до всего количества строк.
- Цикл будет проходить по каждой строке в документе.

6. Вызываем метод для пересчёта одной строки
```python
   self._rebuild_line_tokens(line_num) 
```
- `self._rebuild_line_tokens(...)` — вспомогательный метод, который пересчитывает токены только для одной строки.
- Передаём ему номер строки.
- Он сам разберётся, как лексировать строку и сохранить токены в кэш.

7. Обновляем сохранённый текст документа
```python
    self._document_text = doc.toPlainText()
```
- `doc.toPlainText()` — возвращает весь текст документа.
- `self._document_text` — переменная, в которой хранится последний известный текст.
- Сохраняем новый текст, чтобы сравнивать с ним в следующий раз.
**Зачем?**
Чтобы не пересчитывать кэш, если текст не изменился.

**Итого:**
Метод:*
*Очищает старый кэш токенов.*
*Проверяет, нужно ли пересчитывать (установлен ли язык и есть ли текст).*
*Проходит по каждой строке документа.*
*Пересчитывает токены для каждой строки (с помощью `_rebuild_line_tokens`).*
*Сохраняет новый текст, чтобы не делать лишнюю работу в следующий раз.*
*Это полная пересборка кэша, которая занимает время, но гарантирует, что все токены актуальны.*

### `_apply_1c_highlighting(self, text: str)`

Этот метод применяет цветовую подсветку к текущей строке, если язык установлен как 1c. 
Он использует заранее подготовленные токены (например, Функция, Перем, +), чтобы быстро раскрасить текст.

1. Получаем номер текущего блока (строки)
```python
    current_block_number = self.currentBlock().blockNumber() + 1
```
- `self.currentBlock()` — возвращает текущий блок (строку), которую Qt сейчас подсвечивает.
- `.blockNumber()` — возвращает номер строки, начиная с 0 (как в программировании).
- `+ 1` — прибавляем 1, потому что люди считают строки с 1.
- Сохраняем номер строки в переменную current_block_number.
```text
    Пример:
    Если Qt обрабатывает строку 5, то current_block_number = 5.
```
Пример:
Если Qt обрабатывает строку 5, то current_block_number = 5.

2. Получаем токены для этой строки из кэша
```python
   tokens_for_line = self._tokens_by_line.get(current_block_number, []) 
```
- `self._tokens_by_line` — словарь, в котором хранятся токены для каждой строки.
- `.get(...)` — безопасно получает токены для строки current_block_number.
- Если строки нет в кэше, возвращает пустой список [].
- Сохраняем токены в переменную tokens_for_line.
```text
Пример:
Если строка 5 содержит Функция Тест(), то tokens_for_line может быть:
```
```python
[
    {'start': 0, 'length': 7, 'type': 'FUNCTION_KEYWORD', 'text': 'Функция'},
    {'start': 8, 'length': 5, 'type': 'IDENTIFIER', 'text': 'Тест'},
    ...
]
```
3. Если токенов нет — используем резервный метод
```python
    if not tokens_for_line:
        self._fallback_1c_highlighting(text)
        return
```
**Зачем?**
Потому что кэш мог не успеть обновиться, или строка была пустой.

4. Проходим по всем токенам этой строки
```python
    for token_data in tokens_for_line:
```
- `tokens_for_line` — список токенов для текущей строки.
  - Цикл проходит по каждому токену.
    - `token_data` — словарь, содержащий информацию о токене:
    - `'start'` — позиция токена в строке,
    - `'length'` — длина токена,
    - `'type'` — тип токена (например, FUNCTION_KEYWORD),
    - `'text'` — сам текст токена (например, Функция).

5. Пробуем применить форматирование
```python
    try:
    self._apply_token_format(
        token_data['start'],
        token_data['length'],
        token_data['type'],
        token_data['text'],
        '1c'
    )
```
- `self._apply_token_format(...)` — метод, который применяет цвет к токену.
- Передаём ему:
    - token_data['start'] — позиция токена,
    - token_data['length'] — длина токена,
    - token_data['type'] — тип токена,
    - token_data['text'] — текст токена,
    - '1c' — язык (нужен, чтобы выбрать правильный цвет).

6. Если возникла ошибка — ловим её
```python
    except Exception as e:
    print(f"Ошибка при подсветке токена в строке {current_block_number}: {e}")
```
Выводим сообщение об ошибке с номером строки.

7. Используем резервный метод и выходим из цикла
```python
    self._fallback_1c_highlighting(text)
    break
```
- Вызываем резервный метод, чтобы подсветить строку, даже если что-то пошло не так.
  - `break` — выходим из цикла, потому что дальше нет смысла продолжать.
**Итого:**
*Метод:*
*Узнаёт номер текущей строки, которую Qt обрабатывает.*
*Получает токены для этой строки из кэша.*
*Если токенов нет, использует резервный метод.*
*Проходит по каждому токену и применяет цвет.*
*Если ошибка, использует резервный метод и останавливает обработку.*
*Это позволяет быстро подсвечивать синтаксис, используя готовые токены, и безопасно справляться с ошибками.*
