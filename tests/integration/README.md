# Интеграционные тесты

## Описание

Интеграционные тесты проверяют взаимодействие различных компонентов системы, в частности:

1. **Интеграцию системы парсинга с моделями данных**
2. **Корректность передачи данных от парсера ST-файлов к модели дерева файлов**
3. **Правильность преобразования структуры данных в формат Qt**
4. **Синхронизацию данных между парсером и моделью при изменении файлов**
5. **Интеграцию редакторов с системой парсинга**
6. **Корректность отображения содержимого файлов в различных типах редакторов**
7. **Правильность применения синтаксической подсветки на основе данных от парсера**
8. **Сохранение изменений, внесенных в редакторе, и обновление данных в модели**
9. **Интеграцию системы наблюдения за файлами (FileWatcher) с кэшем и моделью данных**
10. **Автоматическое обнаружение изменений файлов вне приложения**
11. **Корректное обновление кэша при изменении файлов**
12. **Автоматическое обновление модели дерева файлов при обнаружении изменений**
13. **Интеграцию стартовой панели, реализованной по паттерну MVVM**
14. **Корректность взаимодействия между Model, ViewModel и View**
15. **Правильность обновления представления при изменении данных в модели**
16. **Корректность сохранения и загрузки конфигурации кнопок**

## Структура тестов

### `test_parser_model_integration.py`

Основной файл с интеграционными тестами, содержащий следующие тестовые сценарии:

#### 1. Тест передачи данных от парсера к модели
- **`test_parser_to_model_data_transfer`**: Проверяет корректность передачи данных от парсера ST-файлов к модели дерева файлов. Убеждается, что структура файла корректно извлекается парсером и передается в модель без потерь.

#### 2. Тест преобразования структуры в формат Qt
- **`test_structure_transformation_to_qt_format`**: Проверяет правильность преобразования структуры данных от парсера в формат, используемый моделью Qt. Убеждается, что иерархия элементов сохраняется, типы элементов определяются корректно.

#### 3. Тест синхронизации при изменении файлов
- **`test_data_synchronization_on_file_change`**: Проверяет синхронизацию данных между парсером и моделью при изменении файлов. Убеждается, что при изменении файла модель обновляется корректно, старые элементы удаляются, новые добавляются.

#### 4. Дополнительные тесты
- **`test_model_index_navigation`**: Проверка навигации по индексам модели Qt
- **`test_model_update_removes_old_elements`**: Проверка удаления старых элементов при обновлении
- **`test_tree_model_manager_integration`**: Интеграционный тест с TreeModelManager
- **`test_model_data_roles`**: Проверка различных ролей данных в модели Qt
- **`test_complex_nested_structure`**: Тест обработки сложной вложенной структуры

### `test_editor_parser_integration.py`

Файл с интеграционными тестами для проверки взаимодействия редакторов с системой парсинга:

#### 1. Тест отображения содержимого в ST-редакторе
- **`test_st_editor_displays_parsed_content`**: Проверяет корректность отображения содержимого ST-файла в ST-редакторе. Убеждается, что парсер корректно извлекает содержимое шаблона, и редактор корректно его отображает.

#### 2. Тест отображения содержимого в Markdown-редакторе
- **`test_markdown_editor_displays_parsed_content`**: Проверяет корректность отображения содержимого MD-файла в Markdown-редакторе. Убеждается, что парсер корректно извлекает содержимое, и редактор корректно его отображает.

#### 3. Тест синтаксической подсветки в ST-редакторе
- **`test_st_editor_syntax_highlighting`**: Проверяет правильность применения синтаксической подсветки в ST-редакторе. Убеждается, что язык определяется корректно по маркеру @@, и подсветка применяется на основе данных от парсера.
- **`test_st_editor_language_detection_python`**: Дополнительный тест определения языка Python по маркеру.

#### 4. Тест синтаксической подсветки в Markdown-редакторе
- **`test_markdown_editor_syntax_highlighting`**: Проверяет правильность применения синтаксической подсветки в Markdown-редакторе на основе содержимого от парсера.

#### 5. Тест сохранения изменений и обновления модели
- **`test_st_editor_save_updates_model`**: Проверяет сохранение изменений в ST-редакторе и обновление данных в модели. Убеждается, что изменения корректно сохраняются и модель обновляется.
- **`test_markdown_editor_save_updates_file`**: Проверяет сохранение изменений в Markdown-редакторе и обновление файла на диске.

#### 6. Дополнительные тесты
- **`test_editor_load_from_parser_data`**: Проверяет полный цикл загрузки содержимого в редактор из данных парсера
- **`test_multiple_editors_different_types`**: Проверяет работу с несколькими редакторами разных типов
- **`test_editor_content_modification_tracking`**: Проверяет отслеживание изменений содержимого в редакторе

### `test_file_watcher_integration.py`

Файл с интеграционными тестами для проверки системы наблюдения за файлами (FileWatcher) в интеграции с кэшем и моделью данных:

#### 1. Тест обнаружения изменений файлов
- **`test_file_watcher_detects_external_file_changes`**: Проверяет автоматическое обнаружение изменений файлов вне приложения. Убеждается, что FileWatcher обнаруживает изменения файла, сделанные вне приложения, и испускает соответствующие сигналы (file_updated и debounced_file_updated).

#### 2. Тест обновления кэша
- **`test_cache_updates_on_file_change`**: Проверяет корректное обновление кэша при изменении файлов. Убеждается, что при изменении файла кэш инвалидируется, новые данные парсятся и сохраняются в кэш, и кэш содержит актуальные данные после изменения файла.

#### 3. Тест обновления модели
- **`test_model_updates_on_file_change`**: Проверяет автоматическое обновление модели дерева файлов при обнаружении изменений. Убеждается, что модель обновляется при изменении файла, структура модели соответствует новой структуре файла, и старые элементы удаляются, новые добавляются.

#### 4. Полная интеграция
- **`test_integration_file_watcher_cache_model`**: Проверяет полный цикл интеграции FileWatcher -> Кэш -> Модель. Убеждается, что FileWatcher обнаруживает изменение, кэш обновляется, и модель обновляется через TreeModelManager.

#### 5. Дополнительные тесты
- **`test_file_watcher_pause_resume`**: Проверяет паузу и возобновление отслеживания. Убеждается, что FileWatcher может быть приостановлен, во время паузы изменения не обрабатываются, и после возобновления отслеживание продолжается.
- **`test_multiple_file_changes_rapid`**: Проверяет обработку множественных быстрых изменений файла. Убеждается, что дебаунсинг работает корректно при множественных изменениях и обрабатывается только последнее изменение.

### `test_start_panel_mvvm_integration.py`

Файл с интеграционными тестами для проверки стартовой панели, реализованной по паттерну MVVM:

#### 1. Тест взаимодействия компонентов MVVM
- **`test_model_viewmodel_view_interaction`**: Проверяет корректность взаимодействия между Model, ViewModel и View. Убеждается, что ViewModel корректно делегирует вызовы в Model, испускает сигнал buttonsChanged при изменении данных, и View корректно получает данные через ViewModel.

#### 2. Тест обновления представления
- **`test_view_updates_on_model_change`**: Проверяет правильность обновления представления при изменении данных в модели. Убеждается, что View обновляется при изменении данных через ViewModel, сигнал buttonsChanged вызывает обновление View, и кнопки в UI соответствуют данным в Model.

#### 3. Тест сохранения и загрузки конфигурации
- **`test_save_and_load_configuration`**: Проверяет корректность сохранения и загрузки конфигурации кнопок. Убеждается, что конфигурация корректно сохраняется в JSON файл, корректно загружается из JSON файла, и после перезагрузки данные восстанавливаются.

#### 4. Тест сигналов ViewModel
- **`test_view_model_signals_on_all_operations`**: Проверяет испускание сигналов ViewModel при всех операциях. Убеждается, что сигнал buttonsChanged испускается при добавлении, удалении, редактировании и сортировке кнопок.

#### 5. Полный цикл MVVM
- **`test_full_mvvm_cycle`**: Проверяет полный цикл MVVM - добавление, редактирование, удаление, сохранение, загрузка. Убеждается, что все операции работают корректно в связке.

#### 6. Дополнительные тесты
- **`test_view_model_validation`**: Проверяет валидацию данных в ViewModel. Убеждается, что ViewModel корректно валидирует данные через Model и некорректные данные не добавляются.
- **`test_multiple_views_same_viewmodel`**: Проверяет работу нескольких View с одним ViewModel. Убеждается, что изменения в одном View отражаются во всех View.
- **`test_configuration_file_format`**: Проверяет формат файла конфигурации. Убеждается, что файл конфигурации имеет правильный JSON формат, содержит все необходимые поля и корректно обрабатывается при загрузке.

## Запуск тестов

### Запуск всех интеграционных тестов:
```bash
pytest tests/integration/
```

### Запуск конкретного тестового файла:
```bash
pytest tests/integration/test_parser_model_integration.py
pytest tests/integration/test_editor_parser_integration.py
pytest tests/integration/test_file_watcher_integration.py
pytest tests/integration/test_start_panel_mvvm_integration.py
```

### Запуск с подробным выводом:
```bash
pytest tests/integration/test_parser_model_integration.py -v
pytest tests/integration/test_editor_parser_integration.py -v
pytest tests/integration/test_file_watcher_integration.py -v
pytest tests/integration/test_start_panel_mvvm_integration.py -v
```

### Запуск с покрытием кода:
```bash
pytest tests/integration/ --cov=src --cov-report=html
```

## Требования

- Python 3.8+
- PySide6 (для работы с Qt моделями)
- pytest
- Все зависимости из `requirements.txt`

## Примечания

- Тесты используют временные файлы, которые автоматически удаляются после выполнения
- Для работы с Qt моделями требуется инициализация QApplication (выполняется автоматически в `setUpClass`)
- Кэши (ContentCache, MetadataCache) очищаются после каждого теста
